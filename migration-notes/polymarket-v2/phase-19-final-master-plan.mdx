## Verified auth headers

L1 (POST `/auth/api-key`): `POLY_ADDRESS, POLY_SIGNATURE, POLY_TIMESTAMP, POLY_NONCE`

L2 user (per-user, derived from L1): `POLY_ADDRESS, POLY_SIGNATURE, POLY_TIMESTAMP, POLY_API_KEY, POLY_PASSPHRASE`

Builder attribution (added on top of L2 user for `POST /order`): `POLY_BUILDER_API_KEY, POLY_BUILDER_PASSPHRASE, POLY_BUILDER_SIGNATURE, POLY_BUILDER_TIMESTAMP`

Relayer simple auth (for relayer endpoints): `RELAYER_API_KEY, RELAYER_API_KEY_ADDRESS` (no HMAC)

Relayer builder auth (alt for `POST /submit`): same 4 `POLY_BUILDER_*` headers as builder attribution

HMAC algorithm: `base64-decode(secret) → hmac-sha256(timestamp+method+normalizedPath+body) → base64 → URL-safe replace +/→-_`. Identical to our `src/lib/hmac.ts:8-20`.

L1 typed data is `ClobAuthDomain v1` with `ClobAuth` primary type and 4 fields `address(address), timestamp(string), nonce(uint256), message(string)`. Identical to our `src/lib/trading-auth/client.ts`. Message: `"This message attests that I control the given wallet"`.
