## What Prior Codex Work Already Did

The repository already contains `migration-notes/polymarket-v2/phase-00-framework.mdx` through `phase-19-final-master-plan.mdx`, plus `v2-audit.md` and `v2-spec.md`.

Useful work already captured:

- Polymarket V2 migration was decomposed into markets, pricing, user data, trading, wallet/auth, websockets, comments, admin/crons, geoblock, builder, and cutover phases.
- The current app already has partial Polymarket V2 support: Gamma event sync, V2-style order signing, V2-style CLOB order bodies, proxy wallet maker support, relayer `/submit`, pUSD onramp wrapping, native comments, and data-api wrappers.
- Prior notes correctly identified that Kuest/Axes was built close to Polymarket shape, so this is mostly endpoint, auth, wallet, and contract-alignment work rather than a full product rewrite.

Corrections to prior notes:

- Some prior phase docs contain copied environment values and secrets. Treat those files as sensitive, redact them before sharing, and rotate all exposed Polymarket builder/relayer credentials before production.
- Some prior notes mention old gamma/volume cron assumptions. Current `vercel.json` only schedules `/api/sync/events`, `/api/sync/resolution`, and `/api/sync/translations`.
- Current official CLOB OpenAPI for `POST /order` uses user L2 headers and a signed order containing the `builder` bytes32 field for builder attribution. Do not invent builder HMAC headers for `/order`.
- Current official CTF/pUSD docs require pUSD as trading collateral. Current app still has several split/merge/redeem paths defaulting to USDC.e or legacy UMA adapter addresses.

## Official Polymarket Facts That Matter For Launch

### Builder Program

Official source:

- `https://docs.polymarket.com/builders/overview.md`
- `https://docs.polymarket.com/builders/tiers.md`
- `https://docs.polymarket.com/builders/api-keys.md`
- `https://docs.polymarket.com/builders/fees.md`
- `https://docs.polymarket.com/trading/orders/attribution.md`

Builder launch constraints:

- Builder attribution is carried by the signed CLOB order `builder` field.
- The builder code must be a bytes32 value.
- Builder API keys are created through `POST /auth/builder-api-key` using standard user L2 auth.
- Builder fees and tiers are official program mechanics. Internal Axes affiliate logic can remain for product tracking, but partnership reporting should key off official builder volume/trades/fees.
- Official CLOB `/builder/trades` takes a `builder_code` query param.

### CLOB Trading

Official source:

- `https://docs.polymarket.com/trading/overview.md`
- `https://docs.polymarket.com/trading/orders/create.md`
- `/tmp/polymarket-clob-openapi.yaml`

Current CLOB order schema requires:

- `salt`
- `maker`
- `signer`
- `tokenId`
- `makerAmount`
- `takerAmount`
- `side`
- `expiration`
- `timestamp`
- `builder`
- `signature`
- `salt`
- `signatureType`

Current CLOB send body:

- Top-level `order`.
- Top-level `owner`.
- Optional `orderType`.
- Optional `deferExec`.

Current CLOB auth:

- User L2 headers: `POLY_API_KEY`, `POLY_ADDRESS`, `POLY_SIGNATURE`, `POLY_PASSPHRASE`, `POLY_TIMESTAMP`.
- For this app, those user L2 credentials are stored in `user_clob_auth`.

### Gasless Wallets And Relay

Official source:

- `https://docs.polymarket.com/trading/gasless.md`
- `https://docs.polymarket.com/api-reference/relayer/introduction`
- `/tmp/polymarket-relayer-openapi.yaml`
- `../polymarket/wagmi-safe-builder-example`
- `../polymarket/magic-safe-builder-example`
- `../polymarket/turnkey-safe-builder-example`
- `../polymarket/privy-safe-builder-example`

Gasless launch constraints:

- User has an EOA signer.
- Trading happens from a proxy wallet or Safe/funder address.
- Proxy/Safe orders use `signatureType = 2`.
- CLOB order `maker` should be the proxy wallet/Safe.
- CLOB order `signer` should be the user EOA.
- Relayer endpoints use builder/relayer credentials server-side.
- Do not expose builder API key, passphrase, or secret to the browser. Some example signing routes are reference-only and must not be copied into production as-is.

Current recommendation:

- Keep Reown + Wagmi for this week because the app already uses it and current code already supports proxy wallet signing.
- Defer Magic/Turnkey migration unless there is a business requirement. Changing wallet provider and backend trading at the same time adds unnecessary launch risk.

### pUSD And CTF

Official source:

- `https://docs.polymarket.com/trading/ctf/overview.md`
- `https://docs.polymarket.com/trading/ctf/split.md`
- `https://docs.polymarket.com/trading/ctf/merge.md`

- `https://docs.polymarket.com/resources/contracts.md`
- `../polymarket/ctf-exchange-v2/README.md`

Current contract facts:

- pUSD is the collateral for current Polymarket trading.
- pUSD address: `0xC011a7E12a19f7B1f670d46F03B03f3342E82DFB`.
- CTF Exchange V2: `0xE111180000d2663C0091e4f400237545B87B996B`.
- NegRisk CTF Exchange V2: `0xe2222d279d744050d28e00520010520000310F59`.
- Conditional Tokens: `0x4D97DCd97eC945f40cF65F87097ACe5EA0476045`.
- CTF Collateral Adapter: `0xADa100874d00e3331D00F2007a9c336a65009718`.
- NegRisk CTF Collateral Adapter: `0xAdA200001000ef00D07553cEE7006808F895c6F1`.
- Official docs also list a NegRisk Adapter address: `0xd91E80cF2E7be2e162c6513ceD06f1dD0dA35296`.

Launch implication:

- Deposit UX can accept USDC.e and wrap to pUSD through the onramp.
- Trading approvals and CTF operations must operate on pUSD and current V2 adapters, not old UMA adapter defaults.
- Split, merge, redeem, and convert paths need the highest-risk review before live launch because they move user assets and are currently less aligned than order submission.

### WebSockets

Official source:

- `https://docs.polymarket.com/market-data/websockets/overview.md`
- `https://docs.polymarket.com/market-data/websockets/market-channel.md`
- `https://docs.polymarket.com/market-data/websockets/user-channel.md`
- `https://docs.polymarket.com/market-data/websockets/rtds-channel.md`
- `/tmp/polymarket-asyncapi-market.json`
- `/tmp/polymarket-asyncapi-user.json`
- `/tmp/polymarket-asyncapi-sports.json`

Current endpoints:

- Market channel: `wss://ws-subscriptions-clob.polymarket.com/ws/market`
- User channel: `wss://ws-subscriptions-clob.polymarket.com/ws/user`
- Sports channel: `wss://sports-api.polymarket.com/ws`
- RTDS: `wss://ws-live-data.polymarket.com`

Heartbeat requirements:

- Market/user channels: client sends `PING` every 10 seconds.
- Sports channel: server sends `ping`, client responds `pong`.
- RTDS: client sends `PING` every 5 seconds.

Launch implication:

- Current app has websocket consumers, but heartbeat handling is incomplete or absent.
- User channel is not implemented in the reviewed app paths.
- RTDS comment events are documented. RTDS activity topic used by the app is not confirmed in the official docs snapshot and must be verified or replaced.

### Gamma And Comments

Official source:

- `https://docs.polymarket.com/api-reference/gamma/introduction`
- `/tmp/polymarket-gamma-openapi.yaml`
- RTDS comment docs in `llms-full`.

Gamma facts:

- `/events/keyset` supports cursor-based event sync.
- Event payloads include tags, markets, comment counts, restricted flag, neg-risk fields, liquidity fields, and creator/source fields.
- `/comments` supports `parent_entity_type` and `parent_entity_id`.
- RTDS comments emit `comment_created`, `comment_removed`, `reaction_created`, and `reaction_removed`.

Launch implication:

- Native Axes comments can be seeded from Gamma and kept local.
- Unless a supported authenticated Gamma comment write API is confirmed, Axes comments should be treated as local comments, not upstream Polymarket global comments.

Current state:

- EIP-712 domain is V2: `Polymarket CTF Exchange`, version `2`.
- Order type includes V2 fields: `salt`, `maker`, `signer`, `tokenId`, `makerAmount`, `takerAmount`, `side`, `signatureType`, `timestamp`, `metadata`, `builder`.

Launch risks:

- `deferExec` is optional in the current CLOB schema and is not sent. This is acceptable if default execution is confirmed live, but adding explicit `deferExec: false` would make intent clearer.
- Cancel actions need live verification against current CLOB `DELETE` bodies.

## P0 Launch Blockers

1. Rotate and redact exposed Polymarket credentials.

Prior migration docs and local env material include sensitive values. Before any deployment or push, rotate builder/relayer credentials and redact docs. Do not publish the existing notes as-is.

2. Set explicit production Polymarket envs.

Current defaults still point to Axes. Required production values:

```bash
GAMMA_URL=https://gamma-api.polymarket.com
CLOB_URL=https://clob.polymarket.com
DATA_URL=https://data-api.polymarket.com
RELAYER_URL=https://relayer-v2.polymarket.com
WS_CLOB_URL=wss://ws-subscriptions-clob.polymarket.com
WS_LIVE_DATA_URL=wss://ws-live-data.polymarket.com
```

Also configure builder credentials, builder code, admin wallet settings, cron secret, and bridge URL if bridge routes are enabled.

3. Schedule the missing sync jobs.

`/api/sync/gamma`, `/api/sync/tags`, and `/api/sync/gamma-comments` exist but are not scheduled in `vercel.json`.

4. Enforce geoblock in `src/proxy.ts`.

Status endpoints exist. Enforcement does not.

5. Fix CTF collateral and adapter usage.

Split, merge, redeem, and neg-risk conversion paths still default to USDC.e or legacy UMA adapter usage. Current Polymarket trading uses pUSD and V2 adapters.

6. Fix relayer `/submit` response handling.

Current Relayer OpenAPI returns `transactionID` and state from `/submit`; app actions must persist that ID and poll `/transaction` for transaction hash/final state.

7. Add websocket heartbeats and verify RTDS topics.

Official docs require PING intervals. Current reviewed clients do not send them. User channel is missing. RTDS activity topic is unverified.

8. Resolve old Axes-only dependencies.

`USER_PNL_URL`, `COMMUNITY_URL`, `GEOBLOCK_URL`, create-market infrastructure, and `DATA_URL/referrers` cannot be assumed to work as part of Polymarket cutover.

9. Fix confirmed market-level neg-risk domain selection bugs.

Order signing must use the correct exchange domain for each market. The current event order form computes market-level neg-risk but signs with the event-level flag, which can produce the wrong EIP-712 domain.

10. Fix `/data/orders` query and response normalization.

Remove or live-verify the undocumented `maker` query parameter and normalize documented `order_type`.

## Decisions For Launch

Use Reown + Wagmi this week.

Reason: current app is already wired for it, and current order signing supports proxy wallet maker/signature type. Switching to Magic or Turnkey during the same launch window increases risk without being required by Polymarket.

Treat comments as Axes-native comments seeded from Gamma.

Reason: read and seed flows exist. Upstream write support was not confirmed in the official docs reviewed here.

Treat builder program as the official partnership/fee layer.

Reason: the signed order builder field, builder API key docs, tiers, fees, and builder trade endpoint are official. Internal affiliate records can remain as product analytics, but they are not a substitute for builder reporting.

Block all CTF operations until pUSD/adapters are corrected.

Reason: these functions move user assets and currently contain the largest documented mismatch between app code and current Polymarket contracts.

Do not rely on Axes defaults.

Reason: defaults in `next.config.ts` still point to Axes infrastructure. Production must use explicit Polymarket env values.
