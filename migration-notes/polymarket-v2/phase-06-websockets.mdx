# Phase 6. WebSockets

## Scope

Real-time event channels: market book/trade updates, user-level order/trade
events, sports score events, and comment streams. The frontend opens four
distinct websocket connections today; this phase verifies which Polymarket
endpoint each one points at and what subscribe-message shape each one needs.

Out of scope: order placement (Phase 4); comment posting/auth which depends
on the community service host (Phase 7).

## Polymarket reference reading log

Verbatim, this session.

### Polymarket WS endpoint URLs (from `docs.polymarket.com/developers/CLOB/websocket/wss-overview`)

| Channel | URL |
|---|---|
| Market | `wss://ws-subscriptions-clob.polymarket.com/ws/market` |
| User | `wss://ws-subscriptions-clob.polymarket.com/ws/user` |
| Sports | `wss://sports-api.polymarket.com/ws` |

**Phase 0 framework discrepancy.** Phase 0 has `WS_CLOB_URL=wss://ws-subscriptions.polymarket.com` and the same value for `WS_LIVE_DATA_URL`. Polymarket's documented host is `ws-subscriptions-clob.polymarket.com` (note the `-clob` suffix). One of the two is wrong. Action: re-verify by opening a websocket against both and seeing which accepts `/ws/market` connection. See A1 below.

### Market channel subscribe message (verbatim)

```json
{
  "assets_ids": ["token_id_1", "token_id_2"],
  "type": "market",
  "custom_feature_enabled": true
}
```

### User channel subscribe message (verbatim)

```json
{
  "auth": {
    "apiKey": "your-api-key",
    "secret": "your-api-secret",
    "passphrase": "your-passphrase"
  },
  "markets": ["0x1234...condition_id"],
  "type": "user"
}
```

> "The `auth` fields (`apiKey`, `secret`, `passphrase`) are **only required for the user channel**."

Note the asymmetry: market channel subscribes by **token id** (`assets_ids`), user channel by **condition id** (`markets`).

### Market channel operations (verbatim, from `docs.polymarket.com/asyncapi.json`)

| Operation | Direction | Purpose |
|---|---|---|
| `subscribe` | client → server | Initial subscribe with `SubscriptionRequest` |
| `updateSubscription` | client → server | Dynamic add/remove without reconnecting |
| `ping` | client → server | Send `"PING"` every 10s to keep alive |
| `pong` | server → client | Server replies `"PONG"` |
| `receiveBook` | server → client | Full orderbook snapshot on subscribe or after a trade |
| `receivePriceChange` | server → client | Delta to orderbook levels |
| `receiveLastTradePrice` | server → client | Trade execution notification |
| `receiveTickSizeChange` | server → client | Tick size update |
| `receiveBestBidAsk` | server → client | Requires `custom_feature_enabled: true` |
| `receiveNewMarket` | server → client | Requires `custom_feature_enabled: true` |
| `receiveMarketResolved` | server → client | Requires `custom_feature_enabled: true` |

## Findings

### Finding 1. Market channel WS path matches our code; subscribe shape needs verification

**Claim.** `EventMarketChannelProvider.tsx:328` already connects `${wsUrl}/ws/market`, which matches Polymarket's documented path. But the subscribe message body our code sends needs verification — Polymarket's documented shape is `{assets_ids, type:"market", custom_feature_enabled}` and our code's shape isn't visible from the grep alone.

**Evidence.** Code: `:244` shows `ws.send(JSON.stringify({...}))` but I haven't read the object body in detail this turn.

**Impact.** Easy fix if our shape doesn't include `type:"market"` or uses a different field name for token ids. Medium effort if the message format diverges meaningfully.

**Confidence.** Medium until verified at implementation time.

### Finding 2. `useLiveSeriesWebSocket`, `useLiveChartStream`, and `ActivityFeed` connect to root path; Polymarket has no root-path channel

**Claim.** Three hooks/components connect to `${WS_LIVE_DATA_URL}` directly, with no path. Polymarket's WS host expects `/ws/market`, `/ws/user`, or (sports host) `/ws`. Connecting to root path will likely 404 on the upgrade request.

**Evidence.** Live probe needed at implementation time. Code: `useLiveSeriesWebSocket.ts:210`, `useLiveChartStream.ts:323`, `ActivityFeed.tsx:430`.

**Impact.** Three live-data features go dark on cutover: live series chart on event page, live updates on hero carousel, live activity feed. UX degradation but not blocking — features render the polled-data baseline instead.

**Confidence.** High that these will fail; medium on whether Polymarket has an alternate path that semantically matches what these hooks expect.

### Finding 3. `WS_CLOB_URL` and `WS_LIVE_DATA_URL` host name in Phase 0 framework may be missing the `-clob` suffix

**Claim.** Phase 0 framework lists `WS_CLOB_URL=wss://ws-subscriptions.polymarket.com`. Polymarket's docs use `wss://ws-subscriptions-clob.polymarket.com`.

**Evidence.** Phase 0 framework line 60-61. Polymarket WS overview doc, this session.

**Impact.** Critical — wrong host name fails before any subscribe message is sent.

**Confidence.** High that the docs use the suffixed form. The phase-0 author may have used a redirect-friendly alias; need to test both.

### Finding 4. Comments WS doesn't live on Polymarket's CLOB ws host

**Claim.** `useLiveCommentsChannel.ts` connects to `WS_LIVE_DATA_URL` and listens for comment updates. Polymarket's CLOB ws host has no comments channel per asyncapi.json. Comments live on the community service (Phase 7).

**Evidence.** asyncapi.json operation list above. No comment-related operation.

**Impact.** Comments live updates won't work post-cutover. Phase 7 owns this.

**Confidence.** High.

### Finding 5. PING/PONG cadence is 10s; reconnect helper handles this

**Claim.** Polymarket requires a `"PING"` from the client every 10 seconds. Our `websocket-reconnect.ts` has a ping/pong helper. Confirm interval is configurable to 10s.

**Evidence.** AsyncAPI doc states 10s. `websocket-reconnect.ts` not read in detail this turn.

**Impact.** If our default is longer (e.g. 30s), Polymarket may close the connection. Low effort to adjust.

**Confidence.** Medium until interval verified.

## Risks

1. **A2 subscribe-message change can silently lose updates.** If we send the wrong shape, Polymarket may accept the connection but never deliver events. Mitigation: assert on first event arrival within a 10s timeout; fail loud in dev.

2. **A3 widens scope quickly.** Each of the three live-data hooks has its own consumer surface; refactoring all of them at once is a hazard. Mitigation: tackle one at a time. Probably hero carousel first (least UX impact if degraded), event live chart last (most user-visible).

3. **Auth in subscribe message exposes secret to the network if not careful.** Polymarket's user channel spec puts `secret` in the subscribe JSON. Make sure all transports are wss:// (TLS), not ws://. Mitigation: refuse to connect if URL doesn't start with `wss:`.
