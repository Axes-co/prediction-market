# Phase 23 - Verification of Phase 0

This phase independently verifies Codex's Phase 0 claims (Phase 20 / Phase 21 / Phase 22) against current code with file:line evidence. No code changed.

## What I verified vs what Codex claimed

### Claim A. `next.config.ts` defaults all production URLs to Axes hosts

**Codex citation:** `next.config.ts:101-112` (Phase 22 line 67).

**Independent read:** confirmed at `next.config.ts:96-113`. The `env` block exposes 12 URLs to the browser bundle via Next.js `env` (these become `process.env.X` at runtime in client code, not server-only):

```
101  CREATE_MARKET_URL: process.env.CREATE_MARKET_URL ?? 'https://create-market.axes.co',
102  GAMMA_URL:         process.env.GAMMA_URL         ?? 'https://gamma-api.axes.co',
103  GEOBLOCK_URL:      process.env.GEOBLOCK_URL      ?? 'https://geoblock.axes.co',
104  CLOB_URL:          process.env.CLOB_URL          ?? 'https://clob.axes.co',
105  RELAYER_URL:       process.env.RELAYER_URL       ?? 'https://relayer.axes.co',
106  DATA_URL:          process.env.DATA_URL          ?? 'https://data-api.axes.co',
107  USER_PNL_URL:      process.env.USER_PNL_URL      ?? 'https://user-pnl-api.axes.co',
108  COMMUNITY_URL:     process.env.COMMUNITY_URL     ?? 'https://community.axes.co',
109  SDK_DOWNLOAD_URL:  process.env.SDK_DOWNLOAD_URL  ?? 'https://sdk-download.axes.co',
110  PRICE_REFERENCE_URL: process.env.PRICE_REFERENCE_URL ?? 'https://price-reference.axes.co',
111  WS_CLOB_URL:       process.env.WS_CLOB_URL       ?? 'wss://ws-subscriptions-clob.axes.co',
112  WS_LIVE_DATA_URL:  process.env.WS_LIVE_DATA_URL  ?? 'wss://ws-live-data.axes.co',
```

**Verdict:** Confirmed. Codex correct.

**New finding I add:** placing these inside `next.config.ts:env` is not a secret leak (they are public URLs), but it does mean if Vercel envs are unset the production browser bundle silently calls `*.axes.co`. There is no startup check. A misconfigured deploy will silently route real users at Axes infra. This is a launch-time foot-gun, not a runtime hard error.

### Claim B. `src/proxy.ts` does not enforce country blocking

**Codex citation:** `src/proxy.ts:95-108` (Phase 22 line 67), `src/proxy.ts:141-163` (Phase 22 line 68).

**Independent read:** confirmed at `src/proxy.ts:95-164`. The middleware:
- `proxy.ts:98-100` exempts the `/geoblock` page itself.
- `proxy.ts:102-108` short-circuits on `/api/*` after a rate-limit check, never inspecting country headers.
- `proxy.ts:141-163` enforces auth/admin gating only.
- No reference to `x-vercel-ip-country`, `cf-ipcountry`, `cloudfront-viewer-country`, or `isCountryBlocked()` anywhere in the file.

The country header parser exists at `src/lib/geoblock-settings.ts:261-269` (`REQUEST_COUNTRY_HEADERS`) and `src/lib/geoblock-settings.ts:371` (`isCountryBlocked`), but nothing in `src/proxy.ts` calls it.

**Verdict:** Confirmed. Codex correct. Geoblock is read-only / advisory only; no enforcement.

### Claim C. Admin still POSTs to external `GEOBLOCK_URL`

**Codex citation:** `src/app/[locale]/admin/(general)/_actions/update-general-settings.ts:146-165` (Phase 22 line 69, 473).

**Independent read:** confirmed at `update-general-settings.ts:146-165`. The action calls `syncGeoblockSettings()` which `fetch(GEOBLOCK_SYNC_URL, { method: 'POST', ... })`. On Polymarket cutover this either fails (Axes infra is gone) or syncs to a service the new architecture does not control.

**Verdict:** Confirmed. Codex correct.

### Claim D. Phase 16 / Phase 19 contain sensitive material

**Codex citation:** Phase 22 line 70, Phase 21 lines 80, 364.

**Independent grep:**

- `phase-19-final-master-plan.mdx:26` `POLYMARKET_BUILDER_CODE=0x23a45b95958270c7094680b5ee0c572662b167b5ea3abb04dd08862e9fb7e309`
- `phase-19-final-master-plan.mdx:27` `POLYMARKET_BUILDER_ADDRESS=0xcb71e9088a154ac0c6a3fca58eb33e71212b4353`
- `phase-19-final-master-plan.mdx:32` `POLYMARKET_RELAYER_API_KEY_ADDRESS=0xfc34C1726079668396e32bCAEC78481834cF780b`
- `phase-16-live-probe-reference.mdx:21-25` same builder code, builder address, relayer address.
- `phase-16-live-probe-reference.mdx:82-105` real onchain transaction hash + Safe deployment events for the operator wallet.
- `phase-16-live-probe-reference.mdx:559` instruction text referencing `polymarket.com/settings?tab=builder` for builder secret retrieval.

These are wallet *addresses* and a *bytes32 builder code*, not private keys or HMAC secrets. They are public data on-chain. But they identify the Axes operator wallet (`0xfc34c172...780b`, also recorded in my auto-memory `reference_polymarket_creds.md`) and the partnership builder code in a public-friendly migration doc, which is operationally sensitive even if not cryptographically secret.

**Verdict:** Codex's "rotate credentials" framing is an over-statement; nothing in phase-16/19 is a private key, HMAC secret, or session token. But "redact before publishing" is correct because operator wallet identity and builder code do leak partnership identity. Not a credential rotation; an operational disclosure cleanup.

### Claim E. Builder secret naming inconsistency

**Codex citation:** Phase 21 line 81 (`POLYMARKET_BUILDER_SECRET` not `POLYMARKET_BUILDER_API_SECRET`).

**Independent read:** `src/lib/polymarket/relayer-auth.ts:35-37` reads exactly:

```
POLYMARKET_BUILDER_API_KEY
POLYMARKET_BUILDER_SECRET
POLYMARKET_BUILDER_PASSPHRASE
```

`.env.example` contains zero references to any `POLYMARKET_*` env. `src/lib/orders/index.ts:14` reads `POLYMARKET_BUILDER_CODE` but `.env.example` does not document it either.

**Verdict:** Confirmed naming is consistent in code. New finding: `.env.example` is missing **all four** Polymarket builder envs (`POLYMARKET_BUILDER_API_KEY`, `POLYMARKET_BUILDER_SECRET`, `POLYMARKET_BUILDER_PASSPHRASE`, `POLYMARKET_BUILDER_CODE`). A fresh deploy following `.env.example` will fail at trade time with `RelayerAuthMissingError`.

### Claim F. `.env.example` still references kuest auth flow

**Independent read:** `.env.example:5` says `# Get your Kuest CLOB Auth credentials by connecting your EVM wallet (Polygon, 0x...) at https://auth.kuest.com`. The four required envs that follow are still named `POLY_ADDRESS`, `POLY_API_KEY`, `POLY_API_SECRET`, `POLY_PASSPHRASE` (kuest's L2 user auth scheme). Polymarket's CLOB uses the same `POLY_*` names, but the *auth.kuest.com* URL is misleading on a Polymarket migration.

**Verdict:** New finding (not raised by Codex). Documentation rot in `.env.example` will confuse new operators.

## Net Phase 0 P0 list (after my verification)

P0 (must close before launch):

1. Replace `next.config.ts:101-112` Axes defaults with either no fallback (force Vercel envs) or explicit Polymarket production hosts. Add a startup assertion that fails fast if a production deploy resolves to `*.axes.co`.
2. Implement geoblock enforcement in `src/proxy.ts` for both page routes and API mutation routes. Reuse `src/lib/geoblock-settings.ts:isCountryBlocked` rather than re-deriving country logic.
3. Disable or remove `syncGeoblockSettings` in `update-general-settings.ts:146-165` (architecture is now Vercel middleware, not external geoblock service).
4. Document `POLYMARKET_BUILDER_API_KEY`, `POLYMARKET_BUILDER_SECRET`, `POLYMARKET_BUILDER_PASSPHRASE`, `POLYMARKET_BUILDER_CODE`, `CRON_SECRET`, `RELAYER_URL`, `BRIDGE_URL`, `WS_CLOB_URL`, `WS_LIVE_DATA_URL`, and (if used) `BRIDGE_URL` in `.env.example`. Update the `.env.example:5` comment to reference Polymarket auth, not `auth.kuest.com`.

P1 (should close before publishing the migration docs):

5. Redact phase-16 + phase-19 wallet/builder code/transaction hash material before any public commit, push, or PR. The information is public on-chain but discloses partnership identity in a doc-friendly format.

P2 (nice-to-have, not blocking):

6. Decide whether `next.config.ts:env` should expose all 12 URLs to the client or only the ones genuinely needed in the browser bundle (CLOB, WS_CLOB, WS_LIVE_DATA). Server-only URLs (RELAYER_URL, GEOBLOCK_URL, USER_PNL_URL, COMMUNITY_URL, CREATE_MARKET_URL) do not need to be in the client bundle and removing them tightens the surface.

## Corrections to Codex

| Codex framing | My correction |
|---|---|
| "Rotate exposed Polymarket credentials" (Phase 20 P0 #1, Phase 21 #1) | None of phase-16/19 contain private keys, HMAC secrets, or session tokens. Wallet addresses and bytes32 builder code are public on-chain data. Action is **redact for confidentiality**, not **rotate**. |
| "next.config.ts env exposes secrets through `env`" (Phase 22 line 78) | Only public URLs are exposed. Builder secrets are read directly via `process.env.POLYMARKET_BUILDER_*` server-side and never appear in `next.config.ts:env`. Server-side secret hygiene is correct. |
| "Set explicit Vercel envs" framed as P0 #2 | Sub-action: also add a runtime fail-fast (`assert !CLOB_URL.endsWith('.axes.co')` in production) so silent misconfiguration cannot hit live users. |
