# Phase 8. Cron jobs + admin sync routes

## Scope

Rationalize the five Vercel crons (`vercel.json:4-25`) and the admin-facing
sync/management routes under `src/app/[locale]/admin/api/`. Decide kept,
repointed, or deleted for each. This phase doesn't introduce new cron
behaviour — it cleans up after Phases 1-7 land.

Out of scope: writing new cron logic for builder fees collection (Phase 10),
or for community comment ingestion (Phase 7 if we ever sync comments locally).

## Findings

### Finding 1. The cron map after Phases 1-7 is mostly unchanged; only `volume` is deleted

**Claim.** Of the five existing crons, three are unaffected by the env switch (events, resolution, translations), one is deleted (volume), and one is fixed and kept (gamma).

**Evidence.** Phase 1 finding 5; Phase 2 A2/A3.

**Impact.** Phase 8 mostly involves deletions and schedule tweaks rather than rewrites.

**Confidence.** High.

### Finding 2. Admin routes are insulated from the migration

**Claim.** The admin API directory talks to our own Postgres; with one exception (CYOM creator that posts to `CREATE_MARKET_URL`), nothing changes.

**Evidence.** Routes listed in code reading log; all reference `OrderRepository`, `EventRepository`, `UserRepository`, etc. — never CLOB / data-api / relayer / community.

**Impact.** No work in Phase 8 for admin routes beyond hiding the CYOM submit button (Phase 4 A5 covers the relayer side; CYOM-specific signer flow can stay disabled).

**Confidence.** High.

### Finding 3. The `gamma_api` allowed-creator source type adds new complexity worth documenting

**Claim.** The recent in-progress change to `allowed-creators/route.ts` adds a `gamma_api` source type alongside `site` and `wallet`. This means an admin can paste a gamma URL (e.g. `https://gamma-api.polymarket.com`) and the app pulls the creator wallets that source provides.

**Evidence.** `git diff src/app/[locale]/admin/api/event-creations/allowed-creators/route.ts` shows the discriminated union extension.

**Impact.** Useful for the migration: lets us point the activity feed and creator-allowlist at the Polymarket gamma source by configuration rather than code change.

**Confidence.** High.

### Finding 4. The `events` cron's overlap with gamma is small; demoting cadence is sufficient

**Claim.** `events/route.ts` reads Goldsky's pnl-subgraph for on-chain CTF metadata that gamma doesn't always surface (e.g. exact `resolved_at` block timestamps, raw payout values for resolved conditions). It does NOT compete with gamma for active-market discovery — gamma is faster there. So we don't need to delete `events` cron, just lower its frequency.

**Evidence.** `events/route.ts:26-45` and the subgraph URL.

**Impact.** Lower compute cost. No data quality regression.

**Confidence.** Medium — needs a final read of the cron's body to confirm what fields it writes that gamma also writes.

## Action items

### A1. Delete the `/api/sync/volume` cron (P0 — restated from Phase 1 A2)

- **Change.** Delete the directory and its `vercel.json` entry.
- **Files.** `src/app/api/sync/volume/`, `vercel.json:13-15`.
- **Dependencies.** Phase 1 A2 / Phase 2 A3.

### A2. Lower `/api/sync/events` cron cadence to `*/30 * * * *` (P1)

- **Change.** Edit `vercel.json:4-7` to `*/30 * * * *`.
- **Why.** Reduces redundant on-chain sync. Gamma already handles 10-min market discovery; the subgraph is filling tail metadata.
- **Test.** After 24h, verify resolution timestamps and payout values are still being populated for newly resolved markets. If not, restore to `*/5`.
- **Files.** `vercel.json`.
- **Dependencies.** None.

### A3. Hide CYOM submit UI when `CREATE_MARKET_URL` is not configured (P1)

- **Change.** In the admin event-creations form (`AdminCreateEventForm.tsx`), check `process.env.CREATE_MARKET_URL` and render a "CYOM is disabled during the Polymarket migration" notice when empty/missing.
- **Why.** Avoid shipping a button that posts to a 404.
- **Files.** `AdminCreateEventForm.tsx` and the form's submit action.
- **Dependencies.** None.

### A4. Document the cron map in CLAUDE.md (P2)

- **Change.** Add a section to `CLAUDE.md` listing the active crons and their schedules. Not a feature change; a visibility win for future maintainers.
- **Files.** `CLAUDE.md`.
- **Dependencies.** A1, A2.

### A5. Consider adding a builder-trades sync cron for Phase 10's revenue dashboard (P3, post-launch)

- **Change.** New cron `/api/sync/builder-trades` that polls
  `clob.polymarket.com/builder/trades?builderCode=$POLY_BUILDER_CODE` on a
  10-min cadence and writes to a `builder_trades` table for the revenue
  dashboard. Required by Phase 10.
- **Files.** New cron file. New schema migration. Phase 10 owns this.
- **Dependencies.** Phase 4 A4 (builder code is being attached), Phase 10
  schema design.

## Risks

1. **A2 demotion may starve the resolution cron.** If `events` and `resolution` were tightly coupled (one populating before the other reads), demoting `events` could delay resolution data. Mitigation: read `resolution/route.ts` before merging A2 to confirm independence.

2. **Admin routes are exposed at `/admin/api/*` paths.** Make sure they remain auth-gated post-migration; Phase 5's auth changes don't accidentally remove the admin gate.
