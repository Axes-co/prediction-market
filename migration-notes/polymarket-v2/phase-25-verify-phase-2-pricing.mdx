## New findings I add (not in Codex)

### F1. `/midpoint` response field is `mid_price`, not `mid`

`/tmp/polymarket-clob-openapi.yaml:903-913` for `/midpoint`:

```yaml
required:
  - mid_price
properties:
  mid_price:
    type: string
```

`src/app/[locale]/(platform)/event/[slug]/_hooks/useEventMidPrices.ts:11-13`:

```ts
interface MidpointApiResponse {
  mid?: string
}
```

`useEventMidPrices.ts:57` reads `payload?.mid`. The official response key is `mid_price`. The code reads `undefined` for every Polymarket midpoint response and silently falls back to `(bid + ask) / 2` (line 38-40). The fallback is mostly correct but masks the spec mismatch.

**P0 fix:** rename `MidpointApiResponse.mid` → `mid_price` and read `payload?.mid_price`. Live verify against `clob.polymarket.com/midpoint?token_id=<id>`.

### F2. Aggressive 4s timeout in production

`src/lib/clob.ts:6` `CLOB_FETCH_TIMEOUT_MS = process.env.NODE_ENV === 'development' ? 1500 : 4000`. The price-history endpoint accepts up to 20 markets per `MAX_BATCH_PRICE_HISTORY_MARKETS` (`priceHistoryApi.ts:19`); on cold caches Polymarket can take longer than 4s for large batches. The catch in `priceHistoryApi.ts:117-122` swallows it into empty arrays, so the user just sees "no data" with no signal.

**P1:** raise the chart-history timeout to 8-10s and add Sentry breadcrumbs on the catch. Codex flagged the swallow generally; this adds the timeout dimension.

### F3. `/midpoints` (plural) not used despite available

`/tmp/polymarket-clob-openapi.yaml:928` defines `/midpoints` for batch midpoint queries. `useEventMidPrices.ts:92-95` issues `Promise.allSettled(uniqueTokenIds.map(fetchMidpointByToken))` — one HTTP call per token. For a 12-outcome event this is 12 round trips when 1 would suffice.

**P2 perf optimization** (not a launch blocker): swap to `/midpoints` for events with >1 token.

### F4. Chart interval values not validated

`buildBatchPriceHistoryRequestBody` at `priceHistoryApi.ts:54-76` accepts `filters.interval` as a free `string`. CLOB OpenAPI `/prices-history` (line 2239) restricts interval to `max|all|1m|1w|1d|6h|1h`. Callers that pass anything else silently produce a 400 that gets swallowed in `:117-122`.

The actual call sites (in `useEventPriceHistory.ts` and home chart code) pass UI-bound values. Should be validated at the boundary.

**P1:** add a `const ALLOWED_INTERVALS` set and reject unknown intervals before sending the request.
