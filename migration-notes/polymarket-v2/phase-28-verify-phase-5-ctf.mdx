# Phase 28 - Verification of Phase 5

Independent verification of Codex's Phase 5 claims (Phase 22 lines 275-308, Phase 21 lines 188-209, Phase 20 lines 472-503). This phase moves user assets so it has the highest blast radius after order signing.

## Confirmations of Codex's findings

### Contract constants are correct on paper

`src/lib/contracts.ts` defines:
- `:8` `COLLATERAL_TOKEN_ADDRESS = 0x2791…4174` (USDC.e mainnet)
- `:13` `CONDITIONAL_TOKENS_CONTRACT = 0x4D97…6045`
- `:19` `CTF_EXCHANGE_ADDRESS = 0xE111…996B`
- `:20` `NEG_RISK_CTF_EXCHANGE_ADDRESS = 0xe2222…0F59`
- `:25` `NEG_RISK_ADAPTER_ADDRESS = 0xd91E…5296` (V2)
- `:29` `PUSD_ADDRESS = 0xC011…E82DFB`
- `:30` `COLLATERAL_ONRAMP_ADDRESS = 0x9307…5B8ee`
- `:31` `COLLATERAL_OFFRAMP_ADDRESS = 0x2957…dc5854`
- `:36` `UMA_NEG_RISK_ADAPTER_ADDRESS = 0x7242…4d76` (V1 legacy)

Both V2 (`NEG_RISK_ADAPTER_ADDRESS`) and V1 legacy (`UMA_NEG_RISK_ADAPTER_ADDRESS`) addresses exist. The V2 address is documented but **not used** by any safe-transaction default. **Codex correct.**

### Standard CTF builders default to USDC.e

`src/lib/safe/transactions.ts:419-438` `buildSplitPositionTransaction`:
```ts
args: [
  (args.collateralToken ?? COLLATERAL_TOKEN_ADDRESS) as `0x${string}`, // USDC.e
  ...
]
to: (args.contract ?? CONDITIONAL_TOKENS_CONTRACT)
```

`:440-459` `buildMergePositionTransaction` — same default.
`:480-498` `buildRedeemPositionTransaction` — same default.

Per `https://docs.polymarket.com/concepts/pusd.md`, pUSD is the V2 trading collateral. The V2 `ConditionalTokens` contract at `0x4D97…6045` may still accept USDC.e calls, but **positions split with USDC.e are not interchangeable with pUSD-collateralized positions** — they are separate ERC1155 positionId namespaces. A user splitting with USDC.e cannot trade those tokens against a CLOB book whose positions are pUSD-collateralized.

**Verdict:** CONFIRMED. Standard CTF builders default to wrong collateral.

### Neg-risk builders default to legacy UMA adapter

`src/lib/safe/transactions.ts:380-396` `buildNegRiskSplitPositionTransaction`:
```ts
to: (args.contract ?? UMA_NEG_RISK_ADAPTER_ADDRESS)  // V1
```

`:398-417` `buildNegRiskRedeemPositionTransaction` — same default.
`:461-478` `buildConvertPositionsTransaction` — same default.

Should be `NEG_RISK_ADAPTER_ADDRESS` (V2, line 25 of contracts.ts) for current Polymarket. **Confirmed.**

### Trading onboarding approves legacy UMA adapter, not V2 adapter

`src/app/[locale]/(platform)/_providers/TradingOnboardingProvider.tsx:539-551`:

```ts
buildApproveTokenTransactions({
  spenders: [
    CONDITIONAL_TOKENS_CONTRACT,
    CTF_EXCHANGE_ADDRESS,
    NEG_RISK_CTF_EXCHANGE_ADDRESS,
    UMA_NEG_RISK_ADAPTER_ADDRESS,   // V1
  ],
  operators: [
    CTF_EXCHANGE_ADDRESS,

```

V2 `NEG_RISK_ADAPTER_ADDRESS` (`0xd91E…5296`) is missing. New users complete the approval flow without ever approving the V2 neg-risk adapter, so neg-risk operations on V2 markets revert with insufficient allowance. **Confirmed.**

### `EventMergeSharesDialog` passes UMA_NEG_RISK_ADAPTER_ADDRESS for neg-risk merge

`src/app/[locale]/(platform)/event/[slug]/_components/EventMergeSharesDialog.tsx:214`:

```ts
buildMergePositionTransaction({
  conditionId: conditionId as `0x${string}`,
  partition: [...DEFAULT_CONDITION_PARTITION],
  amount: toMicro(numericAmount),
  parentCollectionId: ZERO_COLLECTION_ID,
  contract: isNegRiskMarket ? UMA_NEG_RISK_ADAPTER_ADDRESS : undefined,
})
```

`buildMergePositionTransaction` encodes `conditionalTokensAbi.mergePositions(collateralToken=USDC.e, ...)`. The UMA neg-risk adapter does not implement `mergePositions(collateralToken, parentCollectionId, conditionId, partition, amount)` — that is the ConditionalTokens ABI. Sending this calldata `to: UMA_NEG_RISK_ADAPTER_ADDRESS` reverts with "function not found" (or silently fails depending on ABI fallback).

**Verdict:** Confirmed broken. Neg-risk merges cannot have worked against this address with the ConditionalTokens ABI.

### `EventSplitSharesDialog` branches at `:209-218`

`buildNegRiskSplitPositionTransaction({ conditionId, amount })` for neg-risk vs `buildSplitPositionTransaction({ ... collateralToken default USDC.e })` for standard. Neg-risk path defaults to UMA adapter (V1); standard path defaults to USDC.e collateral. Both wrong for V2.

## New findings I add (not in Codex)

### F1. `negRiskAdapterAbi.splitPosition` signature differs from `conditionalTokensAbi.splitPosition`

The neg-risk split builder at line 380-396 encodes `splitPosition(conditionId, amount)` — only 2 args. Standard split at line 419-438 encodes `splitPosition(collateralToken, parentCollectionId, conditionId, partition, amount)` — 5 args. This is correct because the V2 NegRiskAdapter's `splitPosition` is a wrapper that handles partition/collateral internally. Sending the calldata to the legacy UMA adapter address but the encoding uses `negRiskAdapterAbi` — need to verify the V1 UMA adapter has the same 2-arg `splitPosition` shape.

If the V1 UMA adapter's `splitPosition` signature differs, all neg-risk splits revert. If it's the same, splits succeed but credit positions to the wrong adapter's namespace.

**P0:** verify the V1 UMA adapter ABI matches `negRiskAdapterAbi`. Either way, switching to V2 is required.

### F2. Convert path uses `negRiskAdapterAbi.convertPositions(marketId, indexSet, amount)`

`buildConvertPositionsTransaction` at `:461-478` encodes `convertPositions(marketId, indexSet, amount)` to `UMA_NEG_RISK_ADAPTER_ADDRESS` (V1). On V2 this should target `NEG_RISK_ADAPTER_ADDRESS` (V2). The function signature may be the same on both adapters (they likely share an interface), but the storage state diverges — converting on V1 affects V1 markets, V2 affects V2.

**P0:** redirect convert to V2 adapter.

### F3. Operator/spender approvals are split, but pUSD as the collateral is implicit

`approve-tokens.ts` (assumed shape) approves spenders/operators on the user's tokens. For V2:
- ERC20 `approve` on pUSD → `CONDITIONAL_TOKENS_CONTRACT`, `CTF_EXCHANGE_ADDRESS`, `NEG_RISK_CTF_EXCHANGE_ADDRESS`, `NEG_RISK_ADAPTER_ADDRESS`.
- ERC1155 `setApprovalForAll(operator, true)` on `CONDITIONAL_TOKENS_CONTRACT` → exchanges + adapter.

If the approval helper currently approves USDC.e (`COLLATERAL_TOKEN_ADDRESS`) instead of pUSD, the user has 0 pUSD allowance against the V2 contracts and trading reverts.

Need to read `buildApproveTokenTransactions` to confirm which token is approved. Worth a follow-up read.

### F4. Off-ramp path is missing entirely

`src/lib/polymarket/onramp.ts` exists and wraps USDC.e → pUSD via `COLLATERAL_ONRAMP_ADDRESS`. Codex flagged the "withdrawal must unwrap pUSD" gap (Phase 22 line 268). I confirm: pUSD docs require the offramp at `0x2957…dc5854` (`contracts.ts:31`), but I did not find a withdrawal flow that calls `CollateralOfframp.unwrap`. Withdrawals likely either don't exist or pull USDC.e from the proxy directly (which won't work because the proxy holds pUSD after deposit).

**P0:** confirm withdrawal flow path. If absent, hide withdraw UI until built.

### F5. CTF Exchange immutability tied to Safe factory

`contracts.ts:39-43` comment: "The V2 CTF Exchange has this factory's address baked into its immutable bytecode, so using the wrong factory makes the V2 Exchange reject our orders." `SAFE_PROXY_FACTORY_ADDRESS = 0xaacFeE…541b`. If anywhere in the app the proxy address is computed off a different factory (e.g., legacy kuest factory), the CLOB rejects orders from that proxy. Worth a sanity check at `safe-proxy.ts`.

## Net Phase 5 P0 list

P0:

1. **Default `buildSplitPositionTransaction`/`buildMergePositionTransaction`/`buildRedeemPositionTransaction` to pUSD** — change `args.collateralToken ?? COLLATERAL_TOKEN_ADDRESS` to `args.collateralToken ?? PUSD_ADDRESS`.

2. **Default `buildNegRiskSplitPositionTransaction`/`buildNegRiskRedeemPositionTransaction`/`buildConvertPositionsTransaction` to `NEG_RISK_ADAPTER_ADDRESS`** — change `args.contract ?? UMA_NEG_RISK_ADAPTER_ADDRESS` to `args.contract ?? NEG_RISK_ADAPTER_ADDRESS`.

3. **Add V2 NEG_RISK_ADAPTER_ADDRESS to onboarding approvals** — `TradingOnboardingProvider.tsx:539-551` should add `NEG_RISK_ADAPTER_ADDRESS` to both `spenders` and `operators` lists.

4. **`EventMergeSharesDialog.tsx:214` neg-risk merge** — replace UMA adapter target with V2 NEG_RISK_ADAPTER_ADDRESS, or use the documented V2 merge path (which may require a different adapter ABI).

5. **Verify pUSD is approved, not USDC.e** — read `buildApproveTokenTransactions` and confirm the token being approved is `PUSD_ADDRESS`. If it approves USDC.e, fix.

6. **Build or hide withdrawal/offramp flow.** No call site for `CollateralOfframp.unwrap` was found. Either implement or hide the withdraw UI.

7. **Live tiny-value tests on Polygon** — split, merge, redeem, neg-risk convert, with pUSD on V2 contracts. Without these tests, every fix above is theoretical.
