# Fresh Phased Launch Audit — 2026-04-30

This file replaces the earlier phase notes. It only records findings backed by
official Polymarket docs, local Polymarket reference repositories, or this app's
code/tests.

## Phase 0 — Scope And Source Of Truth

Evidence:

- Official contracts page says Polymarket contracts are on Polygon mainnet
  chain `137` and lists V2 CTF Exchange, Neg Risk Exchange, CTF, pUSD,
  CollateralOnramp, CollateralOfframp, and Safe factory:
  `https://docs.polymarket.com/resources/contracts`.
- Official pUSD page says pUSD is the trading collateral, has 6 decimals, is
  enforced by CollateralOnramp/CollateralOfframp, and documents `wrap`/`unwrap`:
  `https://docs.polymarket.com/concepts/pusd`.
- Builder overview says orders must attach `builderCode` and gasless onchain
  actions use the relayer:
  `https://docs.polymarket.com/builders/overview`.
- Local app production network is Polygon mainnet:
  `src/lib/appkit.ts`.
- Local contract constants match the official V2 addresses:
  `src/lib/contracts.ts`.

Decision:

- Keep Reown/Wagmi + Safe for this launch. Magic/Turnkey/proxy examples are
  alternative wallet-provider integrations, not required to fix the current
  MetaMask/Safe path.
- Launch readiness requires live production probes. Unit tests are not enough
  for relayer acceptance, Safe deployment, wrap/unwrap, or CLOB order fill.

## Phase 1 — Wallet Identity, Safe, And Deposit Discovery

Findings:

- The deposit token query used `user.address`; if the active MetaMask/Reown
  wallet differed from the persisted session address, the deposit modal could
  show `No LI.FI-supported tokens with balance found.` even when MetaMask held
  Polygon USDC.
- LI.FI token discovery is not sufficient for the launch path because the
  Polymarket wagmi Safe example reads Polygon USDC.e directly, not through
  LI.FI:
  `/Users/khaleelmusleh/Desktop/Projects/Axes/polymarket/wagmi-safe-builder-example/hooks/usePolygonBalances.ts`.
- The app already has a Safe proxy deposit target, so Polygon USDC/USDC.e can
  be transferred directly from the active EOA to the Safe without requesting a
  LI.FI quote.

Fixes applied:

- `src/app/[locale]/(platform)/_components/WalletFlow.tsx` now passes the
  active wagmi account address to the deposit modal, falling back to the user
  session address only if wagmi has no account.
- `src/hooks/useLiFiWalletTokens.ts` now always probes Polygon native USDC and
  USDC.e balances directly with `balanceOf`, merges them into the token list,
  and returns them even if LI.FI endpoints fail.
- `src/hooks/useLiFiQuote.ts` returns a synthetic 1:1 quote for direct Polygon
  USDC/USDC.e deposits so the UI does not block on LI.FI.
- `src/hooks/useLiFiExecution.ts` sends direct Polygon ERC-20 `transfer` calls
  to the Safe and waits for the receipt on a Polygon-pinned public client.

Launch gates:

- Browser-test MetaMask on Polygon with native USDC only: token must appear in
  the deposit modal.
- Browser-test MetaMask on Polygon with USDC.e only: token must appear in the
  deposit modal.
- Submit a tiny direct deposit and verify the Safe receives the ERC-20 transfer.

## Phase 2 — Pending Deposit Activation And pUSD Balance

Findings:

- Official docs expose pUSD as trading collateral and document wrapping through
  CollateralOnramp.
- Public pUSD docs specifically document USDC.e as the wrap asset. The local
  Polymarket `ctf-exchange-v2` source shows `CollateralToken.onlyValidAsset`
  accepts both native USDC and USDC.e, while `CollateralOnramp.wrap` forwards
  the selected `_asset` to that token:
  `/Users/khaleelmusleh/Desktop/Projects/Axes/polymarket/ctf-exchange-v2/src/collateral/CollateralToken.sol`,
  `/Users/khaleelmusleh/Desktop/Projects/Axes/polymarket/ctf-exchange-v2/src/collateral/CollateralOnramp.sol`.
- The deposit modal's Axes balance previously read only USDC.e + pUSD, so a
  native-USDC transfer into the Safe could show `$0.00` even though funds
  arrived.
- `usePendingUsdcDeposit` already detects both native USDC and USDC.e at the
  Safe and builds activation using the token address that actually has funds.

Fixes applied:

- `src/hooks/useProxyDepositBalance.ts` now includes native USDC + USDC.e +
  pUSD in the deposit modal's Axes balance.
- `src/app/[locale]/(platform)/_components/wallet-modal/WalletConfirmStep.tsx`
  invalidates pending-deposit and proxy-balance queries immediately after a
  deposit transfer.
- `src/app/[locale]/(platform)/_components/wallet-modal/WalletSuccessStep.tsx`
  tells users that direct Polygon USDC deposits still need activation before
  they become tradable.

Launch gates:

- Send native USDC to Safe, sign activation, confirm pUSD increases.
- Send USDC.e to Safe, sign activation, confirm pUSD increases.
- Confirm no success state is shown for activation until the relayer returns a
  terminal success or the UI clearly reports pending/failure.

## Phase 3 — Relayer Submit And Polling

Findings:

- Official relayer API says `POST /submit` returns `transactionID` plus
  `STATE_NEW`; the onchain hash is retrieved by polling `GET /transaction?id=`.
  Source: `https://docs.polymarket.com/api-reference/relayer/submit-a-transaction`
  and `https://docs.polymarket.com/api-reference/relayer/get-a-transaction-by-id`.
- The recent-transactions endpoint documents auth headers for `GET /transactions`;
  the single-transaction `GET /transaction` page documents the required `id`
  query parameter and response shape, but does not list builder auth headers.
- Signing the polling request with builder headers can make a submitted wrap
  look stuck even if `/submit` accepted it.

Fixes applied:

- `src/lib/polymarket/relayer-poll.ts` now polls `GET /transaction?id=...`
  with `Accept: application/json` only.
- `tests/unit/relayerPoll.test.ts` asserts the unauthenticated polling headers
  and v2/legacy submit parsing behavior.

Launch gates:

- Submit an activation tx and capture the returned `transactionID`.
- Poll until `STATE_CONFIRMED`; confirm `transactionHash` is available.
- Verify failures surface `STATE_FAILED` or `STATE_INVALID` instead of showing
  success.

## Phase 4 — Withdrawals And Transfers

Findings:

- Official pUSD docs document unwrapping through CollateralOfframp.
- Local app withdrawal flow builds an atomic Safe batch: unwrap pUSD to USDC.e,
  then transfer USDC.e to the destination EOA:
  `src/app/[locale]/(platform)/_components/WalletFlow.tsx`.
- Local helper builds `Offramp.unwrap(asset, recipient, amount)`:
  `src/lib/polymarket/onramp.ts`.
- Current UI intentionally enables Polygon USDC.e withdrawal only:
  `src/app/[locale]/(platform)/_components/wallet-modal/utils.ts`.

Launch gates:

- With pUSD balance, withdraw tiny amount to the active MetaMask address.
- Verify Safe pUSD decreases and destination receives USDC.e.
- Verify wrong-chain and wrong-wallet signing is blocked before signature.
