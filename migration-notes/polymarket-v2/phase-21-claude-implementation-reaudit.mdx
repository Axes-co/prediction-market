## Executive Result

Claude implemented the CLOB V2 order shape, builder code field, proxy wallet maker model, relayer submission direction, Gamma sync direction, pricing endpoint pairing, and native comments direction substantially correctly.

The implementation is not launch-ready. The blockers are not small polish issues; they affect production safety and live trading correctness:

- Production envs and default URLs still fall back to Axes hosts in `next.config.ts`.
- New Gamma/tags/comment sync routes are not scheduled in `vercel.json`.
- Geoblock status routes exist, but `src/proxy.ts` does not enforce blocking.
- pUSD/CTF split, merge, redeem, convert, and approval paths still contain USDC.e and legacy UMA adapter defaults.
- Event order signing uses event-level neg-risk for the EIP-712 domain instead of the active market's neg-risk value.
- Relayer `/submit` handling expects transaction hashes directly, but current Relayer OpenAPI returns `transactionID` plus state and requires polling `/transaction` for the onchain hash.
- Open-orders code sends an undocumented `maker` query param to `/data/orders` and reads `type`, while the current OpenAPI documents `order_type`.
- Websocket clients do not send required PING heartbeats, no authenticated user channel was found, and RTDS activity topic usage is unverified.
- Profile, affiliate, admin, and community flows still depend on old or unverified endpoints.
- Prior Phase 16 and Phase 19 docs contain stale conclusions and sensitive credential material; treat them as obsolete until redacted.

## Phase-by-Phase Re-Audit

- The local app does not expose the example repo's builder-signing route that would return builder headers to the browser.

Findings:

### Phase 1 - Markets, Events, Tags, Gamma Sync

Status: mostly correct, but cron scheduling blocks launch.

Correct work found:

- `src/lib/gamma/client.ts` uses Polymarket Gamma endpoints and keyset pagination for `/events/keyset`.
- `src/lib/gamma/mapper.ts` maps V2-relevant event and market fields, including CLOB token ids, condition ids, neg-risk flags, liquidity, volume, restricted flag, creators, tags, and comment count.
- `src/lib/gamma/repository.ts` persists events, markets, outcomes, tags, source records, and sync metadata.
- `src/lib/gamma/tags-sync.ts` syncs standalone tags.
- `src/app/api/sync/gamma/route.ts`, `src/app/api/sync/tags/route.ts`, and `src/app/api/sync/gamma-comments/route.ts` require cron auth.

Findings:

- `vercel.json` only schedules `/api/sync/events`, `/api/sync/resolution`, and `/api/sync/translations`; it does not schedule `/api/sync/gamma`, `/api/sync/tags`, or `/api/sync/gamma-comments`.
- If no enabled Gamma source exists and `GAMMA_URL` is absent, the Gamma sync source list can be empty even though `GammaClient` has a Polymarket default.
- Outcome upsert uses conflict-do-nothing on `token_id`, so changed outcome labels or indexes will not be refreshed automatically.

Required correction:

- Add Vercel schedules for Gamma events, tags, and Gamma comments.
- Make the source fallback explicit and visible in admin/sync logs.
- Decide whether outcome metadata should be updated on conflict.

### Phase 3 - Trading, CLOB Order Wire, Builder Attribution

Status: core order wire mostly correct, but market-level neg-risk signing is wrong.

Correct work found:

- `src/lib/constants.ts` defines V2 EIP-712 order types with the 11 signed fields required by current Polymarket CLOB V2: `salt`, `maker`, `signer`, `tokenId`, `makerAmount`, `takerAmount`, `side`, `signatureType`, `timestamp`, `metadata`, and `builder`.
- `src/lib/orders/index.ts` sets `maker` to the proxy wallet when present, `signer` to the EOA, `signatureType` to proxy mode, and `builder` to the bytes32 builder code.
- `src/lib/orders/signing.ts` signs only the V2 signed fields.
- `src/app/[locale]/(platform)/event/[slug]/_actions/store-order.ts` sends the expected `/order` body shape with top-level `order`, `owner`, `orderType`, and optional `expiration`.
- CLOB `/order` uses user L2 auth headers, not builder HMAC headers.
- Cancel routes use the CLOB delete endpoints for single, market, and all cancels.

Findings:

- `src/app/[locale]/(platform)/event/[slug]/_components/EventOrderPanelForm.tsx` computes `isNegRiskMarket` from the active market, but signs with `getExchangeEip712Domain(isNegRiskEnabled)`, where `isNegRiskEnabled` is event-level. This is a confirmed bug. The signing domain must use the active market's neg-risk flag.
- `src/app/[locale]/(platform)/profile/_components/PublicPositionsList.tsx` cash-out signing derives neg-risk from `event_enable_neg_risk || neg_risk`; this can over-classify if event-level and market-level data disagree.
- Live order submission, cancel, market order, limit order, GTD, and cash-out paths still need production or staging verification against the official CLOB.

Required correction:

- Use market-level neg-risk for every EIP-712 exchange domain decision.
- Keep event-level neg-risk only for display/metadata unless a market-level value is unavailable and explicitly logged.
- Verify builder trades with `/builder/trades?builder_code=<code>`.
- Fix `/data/orders` usage: remove or live-verify the undocumented `maker` query parameter and normalize `order_type` in addition to legacy `type`.

### Phase 4 - Wallet, Proxy, Relay, pUSD Onramp

Status: mostly correct direction, but live verification is still required.

Correct work found:

- Reown/Wagmi can remain for launch; no forced Magic migration is required by the reviewed builder docs.
- `src/lib/safe-proxy.ts` derives Safe proxy address and signatures using the local Polymarket example pattern.
- `src/app/[locale]/(platform)/profile/_actions/proxy-wallet.ts` submits `SAFE-CREATE` through the relayer with server-side builder headers.
- `src/app/[locale]/(platform)/profile/_actions/approve-tokens.ts` gets Safe nonce and submits batched approvals through relayer `/submit`.
- `src/app/[locale]/(platform)/profile/_actions/trading-auth.ts` creates CLOB L2 auth and no longer needs per-user relayer creds for the server-side builder model.
- `src/lib/polymarket/onramp.ts` builds USDC.e to pUSD wrap and pUSD to USDC.e unwrap calldata.
- `src/app/[locale]/(platform)/portfolio/_actions/pending-deposit.ts` submits pending deposit wrap through the Safe relayer flow.

Findings:

- Relayer nonce/signature behavior should be compared against the current builder SDK with a live small transaction.
- Server-side relayer auth timestamp uses milliseconds, matching local examples, but this should be validated live.
- The app stores placeholder relayer credential fields for backwards compatibility; confirm no runtime path expects real per-user relayer credentials.
- Current Relayer OpenAPI says `POST /submit` returns `transactionID` and `state: STATE_NEW`; it does not return `txHash`. `src/app/[locale]/(platform)/_actions/proxy-wallet.ts`, `src/app/[locale]/(platform)/_actions/approve-tokens.ts`, and `src/app/[locale]/(platform)/portfolio/_actions/pending-deposit.ts` currently extract tx-hash variants and do not poll `GET /transaction`.

Required correction:

- Run a clean new-user flow: connect EOA, derive proxy, deploy proxy, create CLOB key, approve tokens, wrap USDC.e to pUSD.
- Verify no builder credential appears in browser JS, browser network responses, logs, or client env.
- Store relayer `transactionID` and state, then poll `GET /transaction?id=<transactionID>` until a transaction hash or terminal state is available.

## Final Launch Position

Current code is a strong V2 migration base, not a deployable full cutover. The highest-risk code Claude wrote is not the CLOB order body; it is the surrounding production integration layer that determines whether trades sign on the correct exchange, whether positions can be managed with pUSD, whether live data stays connected, whether blocked regions are actually blocked, and whether old Axes services are still required.

Do not launch full production trading until the blockers above are closed and live-tested.
